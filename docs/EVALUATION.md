# 怎么科学地评价一个数字人视频

这份文档回答一个问题：**除了「我看着觉得还行」，还能用什么来判断一条数字人素材好不好。**

代码在 `videometrics/`，命令是 `python3 avatar_lab.py eval <视频>`。

---

## 1. 先把「好」定义清楚

绝大多数数字人评测（包括下面要引用的那份）问的是**拟人度**：这段视频像不像真人拍的。
但我们的素材不是给人看的，是喂给腾讯云数智人平台去**训练一个形象**。目标不同，
「好」的定义也不同：

| | 给人看的成片 | 我们的训练素材 |
| :-- | :-- | :-- |
| 观众 | 人 | 平台的训练算法 |
| 一帧崩了 | 观众可能没注意 | 会被学进模型权重 |
| 身份轻微漂移 | 看不出来 | 学出一张平均脸，糊，且不可逆 |
| 嘴张得不够大 | 显得含蓄 | 学出来的形象永远欠张口 |
| 开头深吸一口气 | 一次性的怪 | 每次合成都会带上这个习惯 |

结论：**训练素材的质量 ≈ 它作为学习样本的信息质量**，而不是观感。
这条区别决定了后面每一个指标的取舍。

## 2. 借来的骨架

参考 AGI-Eval《2026 数字人生成评测报告》（[知乎原文](https://zhuanlan.zhihu.com/p/2052784200860881343)）。
它的方法值得借用，因为规模够大、主客观分离：

- **主观**：770 名真人对 508 组视频做 1–5 分匿名独立打分
- **客观**：10 名内部专家按 **合理性 / 协调性 / 稳定性 / 一致性** 四大维度逐帧标注
- 覆盖 6 大场景、中英双语、图片和语音各分三级难度

它的几个结论直接影响我们的选型：

1. **中文比英文难**，所有模型都是。我们只做中文，所以要按最难的档预期。
2. **口型不匹配是最主要的 AI 痕迹来源**，全行业通病。
3. **牙齿、手部、背景文字**是高频畸变区。
4. 一个反直觉的现象：**Gemini-Omni 口型同步分最高，因为它生成的脸几乎不动**——
   静态正面脸对口型检测工具最友好。这是关于「指标会被钻空子」的最好例子。

我们沿用它的四维，另加两维，并且按使用方确认过的事实重新排了优先级。

### 已确认的三条事实，直接决定了权重

| 事实 | 对指标的影响 |
| :-- | :-- |
| **静默段不参与训练**，只用来链接分割不同的动作 | 静默段的所有判定降为 `info`，只记录、不参与排序 |
| **口型重要但不是决定性**，观众不会盯着嘴看 | 口型问题整体降一级，只有几乎完全不同步才算 `major` |
| **整体协调才是重点**：动作、肢体，以及「脖子处本来不明显的骨骼变得格外显眼」 | 新增 **体态** 维，阈值定得最严，优先级最高 |

第三条特别值得说：颈部骨骼被画出来这个故障，AGI-Eval 报告里归在「解剖质量」，
由大模型按核查清单打分。我们不调大模型，用一个纯几何/纹理的代理量替代，
见下面的 `neck_edge_rise`。

另有一份更细的学术框架 MultiRef-Compass（arXiv:2607.14189，南大/北大/清华/快手等）
提供了两个可以直接抄的设计：
- **粘贴自然度系数**：纯相似度分数有漏洞——把参考图直接贴进视频，相似度反而最高。
  他们让大模型判断人物和场景融不融合，再按系数缩放分数。SkyReels-V3 因此从第 5 名掉到最后。
- **与人类偏好对齐验证**：他们报告自动评分与人工偏好的皮尔逊相关是 **0.90–0.96**。
  这才是一套评测体系有效性的证明方式，见第 5 节。

## 3. 六个维度和具体指标

全部由 `videometrics/facetrack.py` 一次遍历派生：MediaPipe 取 478 个人脸关键点
和 52 个 blendshape、BlazePose 取 33 个身体关键点，OpenCV SFace 取人脸 embedding。

速度：人脸信号逐帧算（口型同步需要），身份向量和体态按每 5 帧抽一次
（都是慢变量）。10 秒素材约 5 秒，80 秒素材约 37 秒。如果全部逐帧跑，
80 秒素材要好几分钟，在 sweep 里逐格算完根本等不起。

### 体态 — 整个人看起来对不对（优先级最高）

| 指标 | 抓什么 |
| :-- | :-- |
| `shoulder_tilt_range` | 肩线倾角的波动范围（度）。身体在变形 |
| `shoulder_width_cv` | 肩宽相对波动。体型不稳 |
| `shoulder_head_ratio_drift` | 肩宽/头高在片中的漂移。人被慢慢改体型 |
| `neck_edge_rise` | **颈部纹理在片中隆起到中位数的几倍** |
| `hand_above_shoulder_frac` | 手抬到肩以上的帧占比（平台要求不遮挡面部颈部） |

`neck_edge_rise` 是针对「脖子骨骼变得格外显眼」设计的。做法：取颈部区域的
拉普拉斯方差（边缘能量），除以**同一张脸上的脸颊区域**做基准——脸颊和颈部
同光照、同样是皮肤，所以比值能把「这条视频整体清晰」和「颈部真长出了结构」分开。

判定用的是**时间维隆起**（p90 ÷ 中位数）而不是绝对比值。原因：绝对值会被
分辨率、肤色、光照整体平移，跨视频不可比；而「某几秒突然长出结构」在同一条
视频内部是可比的。报告里会给出峰值时刻，可以直接跳过去看。

一个实测例子，之前那条 skyreels 成片：

```
(major) 体态/neck_bone_artifact @13.4s: 颈部纹理在片中隆起到中位数的 3.9 倍，
        锁骨/颈筋被画出来了（峰值为脸颊的 0.86 倍）
```

### 协调性 — 嘴有没有跟着声音动

把音频包络（每视频帧一个 RMS）和嘴部开口序列做互相关。

| 指标 | 含义 |
| :-- | :-- |
| `corr_best` | 最佳偏移处的相关系数。这是核心量。 |
| `lag_ms` | 音画偏移。正=嘴慢于声。 |
| `lag_reliable` | 相关性太低或峰值顶在搜索边界时为 false，此时不报偏移 |
| `mouth_range` | 开口幅度的动态范围（p95−p5）。太小 = 小声嘟囔 |

不用 SyncNet 一类判别器，换来两个好处：**确定性**（同输入必同输出，可写回归测试）
和**可解释**（超前多少毫秒是个物理量）。代价是它同样偏爱不动的脸，所以
`corr_best` 必须和活性一起读。

### 一致性 — 全程还是同一个人

| 指标 | 含义 |
| :-- | :-- |
| `embed_sim_mean` / `_min` | SFace 余弦相似度，相对首帧或你给的角色图 |
| `embed_drift_observed` | 线性拟合在**实测区间内**的落差。负 = 单向漂移 |
| `embed_step_min` | 相邻采样点最小相似度，抓突变换人 |
| `mouth_width_ratio_std` | 归一化几何比例的稳定性，抓结构性变形 |

给了 `--image` 时基线是你的角色图（回答「像不像本人」），否则是首帧
（只回答「自己跟自己一致」）。**建议总是传 `--image`。**

### 稳定性 — 有没有抖、跳、漂色

`accel_p99`（人脸中心二阶差分，匀速平移不算抖）、`jump_count` + `jump_times_s`
（跳帧位置）、`freeze_spans_s`（冻结段）、`luma_drift_observed`（亮度漂移）、
`yaw_abs_max`（转头幅度，平台要求正视镜头）。

### 合理性 — 画面本身有没有崩

`face_detect_rate`、`face_miss_longest_s`、`mouth_sharpness_open_*`
（张嘴帧的嘴部拉普拉斯方差，牙齿糊掉时塌下去）、`*_outlier_frac`。

还有两个用于**判断指标本身可不可信**的量：

- `face_px_median`：脸高的像素数
- `detail_metrics_reliable`：脸小于 220px 时为 false

这条很关键。`infinitetalk-fast` 实测输出 **384×576**，脸高只有一两百像素，
这种分辨率下牙齿清晰度和眨眼检测都不可信。所以脸太小时，`no_blink`
会自动从 minor 降为 info 并注明原因，而不是拿一个测不准的量去扣分。

背景文字乱码需要 OCR，暂时留给人眼——对照页会抽 0.3/1/2/3 秒的帧。

### 活性 — 眨眼与静默段（静默部分只记录）

| 指标 | 抓什么 | 级别 |
| :-- | :-- | :-- |
| `blink_count` | 口播段眨眼次数 | minor |
| `silence_frozen` | 静默段帧差近零 = 在放静止帧 | info |
| `silence_open_vs_speech_ratio` | 静默段最大开口 / 口播段 p95 开口 | info |
| `silence_vs_speech_mouth_ratio` | 两段嘴动幅度的标准差之比 | info |
| `silence_jaw_max` | 静默段张颌幅度，吸气的直接证据 | info |

静默段的四项全部是 `info`：既然那段不参与训练，它就不该影响方案取舍。
**仍然测量**，理由有两个：静默段的动作会渗进口播段的开头；换平台档位
（比如阿里高精版要 15 秒静默）时它可能重新变重要。

## 4. 三级严重度，刻意不给总分

`evaluate()` 输出三样东西：指标向量、带时间戳的缺陷清单、每 2 秒一行的时间线。
**没有总分。** 理由：把十几个量纲不同的指标加权成一个数，权重是拍脑袋定的，
那还是主观评价，只是把主观藏进了代码里，还更难质疑。

缺陷分三级，归级依据是使用方的反馈而不是技术直觉：

| 级别 | 含义 | 例子 |
| :-- | :-- | :-- |
| `major` | 会被学进形象且事后无法修复 | 体态畸变、颈部骨骼、身份漂移、跳帧 |
| `minor` | 影响观感但不致命，或能靠提示词/重跑缓解 | 口型偏移、亮度漂移、不眨眼 |
| `info` | 只记录，**不参与排序** | 静默段的一切；分辨率不足导致测不准的项 |

阈值集中在 `videometrics/report.py` 的 `THRESHOLDS`，凭经验定的都标了 **待校准**。
目前真有依据的只有音画偏移（±150ms 是常引用的可感知阈值）和眨眼频率
（成年人静息 10–30 次/分钟），其余都要靠第 5 节的流程定。

排序目前用「重度缺陷数 → 轻度缺陷数」，可辩护（缺陷更少），但不等于更好看。

## 5. 校准流程：让指标去对齐你的偏好

这是整套体系能不能落地的关键一步。

### 为什么不让你打 1–5 分

单个评分者给绝对分不稳：同一条今天 3 分明天 4 分，而且会漂移——
前面看了几条烂的，后面一条中等的就显得好。AGI-Eval 能用 1–5 分是因为有 770 人平均掉噪声。
我们只有你一个人。

**成对比较（A 和 B 哪个好）对单评分者稳定得多**，因为只要求局部判断。

### 具体做法

1. 跑 `python3 avatar_lab.py sweep --image face.jpg`
2. 打开 `data/lab/sweep-screen10/index.html`，切到**盲测**页签
   - 一次只给两条，**不显示模型名和参数**（看见 OmniHuman 会有先验）
   - 左右随机，避免位置偏好
   - 优先安排比较次数最少的组合，让场次均衡（Bradley-Terry 对场次不均衡敏感）
   - 每条比过 3–4 次就够排序，18 条不必投满 153 对
3. 点「导出 votes.json」，放进结果目录
4. 跑 `python3 avatar_lab.py rank data/lab/sweep-screen10`

第 4 步做两件事：

- 用 **Bradley-Terry** 把成对结果拟合成一维能力值（体育排名和 LLM 竞技场用的同一套模型）
- 把 BT 分数和每一个客观指标做 **Spearman 秩相关**

然后就能回答那个真问题：

| 相关系数 | 结论 |
| :-- | :-- |
| 接近 +1 | 这个指标确实预测你的偏好，可以进权重 |
| 接近 0 | 它测的东西你并不在意，别用它排序 |
| 接近 −1 | 方向反了，或者存在钻空子现象（比如脸越不动口型分越高） |

**只有过了这一关，才有资格用指标替你排序。** 在那之前它只是缺陷探测器。

## 6. 已知局限

1. **短片段撑不起「每分钟/每 60 秒」的外推。** 10 秒里多一次眨眼就等于每分钟差 6 次。
   代码里所有漂移量都只报实测区间内的变化，眨眼频率在片长不足 20 秒时不判是否自然。
   这是实测中发现并修掉的问题——早先版本从 7 秒片段外推出「60 秒身份相似度下滑 0.76」，
   而余弦相似度总量程才 2。
2. **口型指标偏爱不动的脸。** 同 AGI-Eval 里 Gemini-Omni 的现象。必须和体态联读。
3. **没有粘贴自然度检测。** 路线 C（角色替换）如果直接贴脸，一致性分会虚高。
4. **背景文字乱码/光影**没有客观指标，只能靠对照页抽帧人眼看。
5. **单评分者。** BT 排名反映的是你的偏好，不是普遍偏好。如果最终形象要给别人看，
   建议再找 2–3 个人各投一轮，看排名是否一致。
6. **分辨率会污染跨模型比较。** 这是 `screen10` 里一个真实的方法论缺陷：
   `infinitetalk-fast` 出 384×576，`skyreels-std` 出 768×1152，两者的
   `mouth_sharpness`、`neck_edge_ratio` 绝对值不可直接比。现在的应对是
   报告 `face_px_median` 并在脸太小时降级相关判定，但**同分辨率对比才是干净的**。
7. **`mouth_sharpness` 受超分影响。** 超分会人为提高清晰度，所以要在同一档
   （都超分或都不超分）之间比较。10 秒筛选矩阵不超分，就是为了这个。
8. **体态指标要求肩部在画面里。** 特写构图（只有头）会让整个体态维失效，
   此时 `note` 会说明原因。

## 7. 已解决和仍待确认的问题

### 已经定了的

| 问题 | 结论 | 已落到代码 |
| :-- | :-- | :-- |
| 静默段画面重不重要 | 不参与训练，只用来链接分割动作 | 静默段判定全部降为 `info` |
| 口型该占多大权重 | 重要但不决定性，观众不盯着嘴看 | 阈值整体降一级 |
| 什么才是重点 | 整体协调：动作、肢体、颈部结构 | 新增体态维，阈值最严 |
| 严重度要几级 | 三级 | major / minor / info |

### 仍待确认

1. **一致性的基线用角色图还是首帧？** 用角色图更严格（要求像本人），
   但如果模型系统性地把人画得更好看，所有方案会被同等扣分，排序不受影响。
   现在两个都支持，传 `--image` 就用角色图。倾向总是传。
2. **`neck_edge_rise` 的阈值（2.5 / 1.7）纯属估计。** 需要用你的主观判断来定：
   在你挑出的那几条和你觉得难看的那几条之间，这个量的分界在哪。
   这是下一轮盲测最该验证的一项。
3. **肩线波动多少算「不自然」？** 现在 minor 6°、major 12°，同样是估的。
   真人口播时肩膀本来就会小幅动，定太严会把正常的自然动作判成缺陷。
4. **10 秒筛出的赢家，在 80 秒上还是赢家吗？** InfiniteTalk 官方说超过 1 分钟
   会明显退化。这就是 `final60` 矩阵要回答的问题。
5. **要不要给体态问题也做时间线定位？** 现在只给颈部峰值时刻。
   肩线和体型漂移目前只有整段的统计量，没有「第几秒开始歪的」。

## 8. 命令速查

```bash
# 入库轮：三个模型跑 80 秒（先看成本）
python3 avatar_lab.py sweep --matrix final60 --image face1.png --dry-run
python3 avatar_lab.py sweep --matrix final60 --image face1.png

# 预算紧就一个一个跑，音频和格子编号保持一致，结果可合并
python3 avatar_lab.py sweep --matrix final60 --image face1.png --only omnihuman

# 对已有视频跑指标，不花钱
python3 avatar_lab.py eval data/lab/sweep-screen10/01-*/03_final.mp4 \
    --silence 2 --image face.jpg

# 连原始指标一起打印
python3 avatar_lab.py eval <视频> --json

# 盲测投票后算排名 + 指标相关性
python3 avatar_lab.py rank data/lab/sweep-screen10

# 只跑指标相关的测试
python3 -m pytest tests/test_videometrics.py -q
AVATAR_TEST_VIDEO=<真人视频> python3 -m pytest -q -m realface
```

依赖：`pip install -r requirements.txt`，Linux 上 mediapipe 还需要
`apt install libegl1 libgles2`。两个模型（3.7MB + 37MB）首次使用时自动下载到
`data/models/`，不进仓库。
