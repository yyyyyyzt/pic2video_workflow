1. 工作流 API

直接调用生成内容

把面板里"导入工作流"保存好的一张张卡片，当成"AI 生成接口"远程调用。三步走：① 提交任务拿 prompt_id；② 轮询查结果；③ 拿到图片/视频/音频的下载 URL。prompt_id 仅存在于 ComfyUI 内存 history 中，重启后失效，请在任务完成时立即保存 results 里的文件 URL，勿依赖隔日再查。下面这段代码可以直接复制到浏览器控制台或 Node 里跑通。

完整示例 · 跑一次工作流并拿到生成结果

QUICKSTART

最常用的接入方式：直接向当前面板地址的 /api/workflow/generate 提交任务，拿到 prompt_id 后再轮询 /api/workflow/result。任务结束后请立刻保存 results 中的 URL；prompt_id 不能作为隔日恢复的凭证。示例里使用完整 URL，复制后更容易看懂。

Step 1 · 提交任务并获取 prompt_id

workflow_id 填「API 生成」页里已经导入保存的工作流名称。input_values 里直接写这个工作流需要改的参数，key 的格式是「节点ID:字段名」。请求成功后返回 data.prompt_id，之后用它查询结果。

执行与查询

5 个接口

完整的调用链：① POST /api/workflow/generate 提交并拿到 prompt_id；② 每隔 1～3 秒 GET /api/workflow/result?prompt_id=… 直到 pending=false；③ 在响应里取 results 数组拿到所有产出文件的 URL。 【prompt_id 有效期】prompt_id 对应 ComfyUI 进程内存中的 history，不会持久化到数据库或磁盘索引。ComfyUI 一旦重启（隔日开机、手动重启、崩溃恢复等），history 清空，旧 prompt_id 将无法再查到结果。单机最多保留约 10000 条历史记录，更早的会被自动挤出。接入建议：① pending=false 时立即把 results 里的 /output/... URL 下载或落库到你方系统；② 不要只保存 prompt_id 指望隔天轮询；③ 若长时间得到 pending=true 且 results=[]，多半是记录已失效（不是任务仍在跑）。

  },

const r = await fetch(BASE_URL + '/api/workflow/generate', {

提交生成任务，立即返回 prompt_id 请求体中的 workflow_id 指定要跑哪条已保存的工作流；接口只负责入队，HTTP 响应里立刻给出 prompt_id，不等待画布跑完。workflow_id 须为已在「API 生成」页导入并保存到面板的工作流。input_values 的 key 为「节点ID:字段名」，例如 "12:image"。文件类参数：① 公网 https URL；② data:*;base64（默认上限约 50MB）；③ 先走上传接口拿到 name 再填入。client_id 可选，用于 WebSocket 进度；不传也可正常使用。

GET /api/workflow/result?prompt_id={prompt_id}
调用示例
// 轮询直到完成
async function waitForResult(promptId) {
  while (true) {
    const r = await fetch(BASE_URL + '/api/workflow/result?prompt_id=' + promptId);
    const data = await r.json();
    if (data.pending === false) return data.results;
    await new Promise(res => setTimeout(res, 1500));
  }
}
const results = await waitForResult(promptId);
results.forEach(r => console.log(r.type, '→', BASE_URL + r.url));
响应示例
{
  "success": true,
  "pending": false,
  "prompt_id": "d1e7a2b8-…",
  "results": [
    {
      "type": "image",
      "url": "/output/2025/zealman_00001.png",
      "filename": "zealman_00001.png"
    },
    {
      "type": "video",
      "url": "/output/2025/zealman_00001.mp4",
      "filename": "zealman_00001.mp4"
    }
  ]
}

推荐：根据 prompt_id 拿到简化结果（图片/视频/音频的可访问 URL） 响应中 pending=true 表示还在跑，请继续轮询；pending=false 即任务结束。results 是数组，按节点输出顺序排列；每个元素包含 type（image/video/audio/text）和 url（output 文件直接是 /output/...，可直接显示或下载）。建议每 1～3 秒轮询一次，避免给后端打满。 注意：当 history 中已无该 prompt_id（例如 ComfyUI 重启后），接口也会返回 pending=true、results=[]，这与「任务仍在生成」无法区分。隔日开机后再用旧 prompt_id 轮询通常查不到结果；请在首次 pending=false 时保存 results。

文件上传

2 个接口

当 input_values 里要传图片/视频/音频，但又不方便用公网 URL 或 base64 时，先把文件上传到 ComfyUI input 目录，拿到返回的 name，再把这个 name 填回 input_values 里对应的字段。

POST /api/comfy/upload/file
请求体
multipart/form-data
  file:      <File>      // 必填，二进制文件
  overwrite: true | false  // 可选，默认 false

（兼容字段名：file / image / video / audio）
调用示例
# curl 上传本地文件
curl -X POST "$BASE_URL/api/comfy/upload/file" \
  -F "file=@/path/to/local.png" \
  -F "overwrite=true"

# 浏览器 fetch + FormData
const fd = new FormData();
fd.append('file', fileInput.files[0]);
fd.append('overwrite', 'true');
const r = await fetch(BASE_URL + '/api/comfy/upload/file', { method: 'POST', body: fd });
const { name } = await r.json();   // 把 name 填到 input_values 里
inputValues['12:image'] = name;
响应示例
{
  "name": "local.png",
  "subfolder": "",
  "type": "input"
}

推荐：通用文件上传，图片/视频/音频/任意文件都可以 Content-Type 必须是 multipart/form-data。字段名兼容 file / image / video / audio 任意一个。overwrite=true 可覆盖同名文件。返回的 name 字段就是给 input_values 用的值。

POST /api/comfy/upload/image
请求体
multipart/form-data
  image:     <File>
  overwrite: true | false

旧兼容接口：仅接受 image 字段（仅图片） 能用 /api/comfy/upload/file 就用它，本接口仅为旧客户端保留。

2. 控制面板 API

面板自身的运维与资产接口

面板自身的运维接口：硬件信息、ComfyUI 启停、资产管理等。面板默认监听 6008 端口，AutoDL 上可通过"自定义服务"暴露到公网。

完整示例 · 自检 + 自动启动 ComfyUI

QUICKSTART

从面板在线自检到 ComfyUI 就绪。左侧为完整脚本；右侧 Step 对应每一段在做什么。

完整调用示例
const BASE_URL = "https://uu11197-78328d7ad669.bjb2.seetacloud.com:8443";

const h = await fetch(BASE_URL + '/api/health')
  .then(r => r.json());
if (h.status !== 'ok') throw new Error('面板未启动');

const gpu = await fetch(BASE_URL + '/api/gpu/info')
  .then(r => r.json());
if (!gpu.hasGPU) throw new Error('当前是无卡模式');
console.log('GPU：', gpu.gpus?.[0]?.name);

let st = await fetch(BASE_URL + '/api/comfy/status')
  .then(r => r.json());

if (!st.running) {
  await fetch(BASE_URL + '/api/comfy/start', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      useProxy: true,
      proxyType: 'network_turbo'
    })
  });
  for (let i = 0; i < 20; i++) {
    await new Promise(r => setTimeout(r, 3000));
    st = await fetch(BASE_URL + '/api/comfy/status')
      .then(r => r.json());
    if (st.running) break;
  }
  if (!st.running) throw new Error('ComfyUI 启动超时');
}
console.log('已就绪 → 端口', st.port);

Step 1 · 定义面板地址

BASE_URL 即当前控制面板地址（与本文档页的 origin 一致）。示例中会替换为实际地址。

Step 2 · 健康检查（面板存活）

/api/health 是最轻量的存活探针。返回 { status: "ok", uptime: 秒数 } 即视为面板可用，常用作监控脚本的就绪探针。

Step 3 · GPU 与无卡模式判断

AutoDL 的「无卡模式」也能开机但跑不了生成。返回里 hasGPU=false 就是无卡模式，需到 AutoDL 控制台正常开机；hasGPU=true 时可在 gpus[] 里看到显卡型号和显存大小。

Step 4 · 查询 ComfyUI 状态

返回 { running, starting, reason, port: 6006, ... }。running=true 直接进入生成流程；running=false 时若 starting=true 说明面板已经在自启动，等几秒再轮询即可；都为 false 才需要主动调用启动接口。

Step 5 · 启动并等待 ComfyUI 就绪

useProxy + proxyType="network_turbo" 会在启动前 source /etc/network_turbo，解决拉模型/插件依赖的网络问题；普通环境可去掉这两个参数。 启动接口立即返回，需要轮询 status 直到 running=true，建议每 3 秒查一次、最多等 60 秒。

ComfyUI 启停 / 状态

9 个接口

ComfyUI（监听 6006）由面板托管，启停、查询、日志均走这里。调用工作流前需先确认 status.running=true。

POST /api/comfy/start
请求体
{
  "useProxy": true,
  "proxyType": "network_turbo",
  "disableCopilot": true
}
调用示例
curl -X POST "$BASE_URL/api/comfy/start" \
  -H "Content-Type: application/json" \
  -d '{"useProxy":true,"proxyType":"network_turbo"}'
响应示例
{
  "code": 0,
  "log": "ComfyUI 启动脚本已触发\\n",
  "alreadyRunning": false
}

启动 ComfyUI（已运行会直接返回 alreadyRunning=true） useProxy=true 时，proxyType 选 "network_turbo"（学术加速，推荐）或 "none"（不使用代理）。disableCopilot=true 可关闭 ComfyUI-Copilot 插件提速。

POST /api/comfy/stop
请求体
{}

停止 ComfyUI（pkill 当前 ComfyUI 进程）

GET /api/comfy/status
响应示例
{
  "running": true,
  "starting": false,
  "reason": "ready",
  "port": 6006,
  "listen": "127.0.0.1",
  "url": "http://127.0.0.1:6006"
}

当前 ComfyUI 是否运行 + 启动阶段 推荐直接用两个布尔字段判断三阶段： • running=true → 启动成功，可直接 generate • running=false, starting=true → 启动中（进程刚起 HTTP 还未就绪、或面板自启动窗口期） • running=false, starting=false → 未启动 reason 字段是调试用的细分原因，可选值： • "ready" ：进程在且 ComfyUI /system_stats 已就绪（== running:true） • "starting" ：进程已起但 HTTP 未就绪，或面板正在自启动等待期 • "process_not_found" ：进程不存在，且没有任何启动流程在跑 建议 generate 前每 2~5 秒轮询一次直到 running=true。

3. 并发接口 API

调度多台 AutoDL 镜像机做批量生成

把多台 AutoDL 实例（镜像机）和本机主控 ComfyUI 当成一个「远程算力池」。面板「并发生成」页分为三块：**机器管理**（Token / 实例 / ComfyUI 启停）、**素材管理**（上传输入文件到 `/root/并发/{image,video,audio}`）、**批量生成**（任务队列与结果预览）。 调用方也可直接走 HTTP API：AutoDL 实例接口需要 Token；镜像机控制与任务调度只需 mirror_url；**本机任务**不传 target_url（或留空）即可在主控 ComfyUI 上跑。文件类 input_values 支持公网 URL、base64、ComfyUI 上传后的 name，以及主控机白名单目录内的**本地绝对路径**（默认 `/root/并发` 及其子目录，可通过环境变量 `CONCURRENT_LOCAL_INPUT_DIRS` 扩展）。

完整示例 · 用 2 台镜像机批量跑同一个工作流

QUICKSTART

从 Token 到多机批跑、拉回结果。左侧为完整脚本；右侧 Step 解释各段含义。

完整调用示例
const BASE_URL = "https://uu11197-78328d7ad669.bjb2.seetacloud.com:8443";
const TOKEN = 'AUTODL_TOKEN_xxxxxxxxxxxxxxxx';

const list = await fetch(BASE_URL + '/api/concurrent/instance/list', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    token: TOKEN,
    page_index: 1,
    page_size: 50
  })
}).then(r => r.json());
const candidates = list.list
  .filter(x => x.status === 'shutdown')
  .slice(0, 2);

for (const ins of candidates) {
  await fetch(BASE_URL + '/api/concurrent/instance/power_on', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      token: TOKEN,
      instance_uuid: ins.instance_uuid
    })
  });
}

const mirrors = [];
for (const ins of candidates) {
  while (true) {
    const url =
      `${BASE_URL}/api/concurrent/instance/snapshot` +
      `?token=${TOKEN}&instance_uuid=${ins.instance_uuid}`;
    const r = await fetch(url).then(r => r.json());
    const dom = r.snapshot?.service_6008_domain;
    if (dom) {
      mirrors.push('https://' + dom);
      break;
    }
    await new Promise(res => setTimeout(res, 5000));
  }
}

for (const m of mirrors) {
  await fetch(BASE_URL + '/api/concurrent/mirror/start', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ mirror_url: m })
  });
}

const inputs = [
  'https://example.com/a.png',
  '/root/并发/image/image_20260709-010435_c7faf2.png',  // 主控白名单本地路径
  'https://example.com/c.png',
];
const submit = await fetch(BASE_URL + '/api/concurrent/run-batch-async', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    workflow_id: 'my-workflow',
    targets: mirrors,
    jobs: inputs.map((src, i) => ({
      id: 'job-' + i,
      input_values: {
        '12:image': src
      }
    }))
  })
}).then(r => r.json());
const runId = submit.run_id;

while (true) {
  const url =
    `${BASE_URL}/api/concurrent/run-batch-status?run_id=${runId}`;
  const s = await fetch(url).then(r => r.json());
  console.log(`${s.done}/${s.total} 完成，错误 ${s.error}`);

  if (['completed', 'cancelled', 'error'].includes(s.status)) {
    for (const job of s.results || []) {
      if (job.status === 'done') {
        const r = await fetch(
          job.target_url + '/api/workflow/result?prompt_id=' + job.prompt_id
        ).then(r => r.json());

        // r.results 里是镜像机上的产出 URL。
        // 用户自己的程序应把这些文件下载到自己的项目存储。
        for (const file of r.results || []) {
          const fileUrl = job.target_url + file.url;
          console.log(job.id, '→', fileUrl);
        }
      }
    }
    break;
  }
  await new Promise(r => setTimeout(r, 2000));
}

Step 1 · 面板地址与 AutoDL Token

BASE_URL 是当前调度接口服务地址；TOKEN 在 AutoDL 控制台申请。用户自己的集群程序可以把它当作调度 API 地址，不需要依赖面板内置的资产管理流程。

Step 2 · 列出实例并挑选镜像机

返回 { list: [{ instance_uuid, status, machine_alias, ... }] }。 status 可能是 running / shutdown / starting。这里挑两台 shutdown 的当镜像机。

Step 3 · 开机（有卡模式）

默认 power_on 是有卡模式（跑生成必须有卡）。省钱场景可加 mode: "shutdown" 走无卡模式，但无卡模式下跑不了生成。

Step 4 · 等待开机并解析镜像机面板 URL

每台镜像机内部也运行着一份面板服务（端口 6008），AutoDL 给它一个对外域名 snapshot.service_6008_domain，前面拼 https:// 就是该镜像机的 mirror_url。 开机需要时间，所以轮询 snapshot 接口直到出现这个字段（5 秒查一次）。

Step 5 · 在各镜像机上启动 ComfyUI

该接口非阻塞，命令发出后镜像机会异步启动 ComfyUI；要确认是否启动完毕，需要轮询 /api/concurrent/mirror/comfy-status。

Step 6 · 提交异步批跑任务

这是并发接口的核心：调度器会在 mirrors/targets 里寻找空闲机器，空闲机器立即接收下一个 job；如果多台机器都在跑，剩余 job 会留在队列里等待，等任意机器完成当前任务后继续派发。这样用户程序只需要提交一批 jobs，不需要自己判断哪台机器空闲。 • workflow_id：要跑的工作流（注意：每台镜像机里都要先有这个工作流文件，否则得先用 /api/workflow/files/update 同步过去） • jobs：每个 job 是一次独立生成；id 任意填，用来在结果里对回去 • input_values 文件字段：可填公网 URL、base64 data URI、ComfyUI 上传后的 name，或主控白名单内的本地绝对路径（如 `/root/并发/image/xxx.png`；可先通过 `/api/concurrent/input-assets/upload` 上传） • targets：可选，不传则用全部可用镜像机 返回 { run_id }，是这次批跑的 ID，用它查进度。

Step 7 · 轮询进度并自行下载结果

每隔 2 秒查一次 run-batch-status：返回 { status, done, total, error, results: [...] }。 当 status 是 completed/cancelled/error 时，遍历 results：每个完成的 job 都有 target_url（哪台镜像机跑的）和 prompt_id（结果 ID）。用户自己的程序应使用 target_url + prompt_id 去对应镜像机查询结果，再把文件下载到自己的项目目录、数据库或对象存储中。

任务调度

8 个接口

对应面板「批量生成」页。单任务可用 generate 指定 target_url（镜像机）或留空跑本机；多任务建议 run-batch / run-batch-async 由调度器排队与负载均衡。文件输入支持 URL 素材与本地素材两种模式（面板切换「URL素材 / 本地素材」）。运行中进度可通过 WebSocket（本机 `/comfyui-ws`、镜像 `/concurrent-mirror-ws`）或 poll/status 获取；跑完后用 result / workflow/result 拉取产物。

POST /api/concurrent/generate
请求体
{
  "workflow_id": "example-workflow.json",
  "jobs": [
    {
      "id": "job-local",
      "input_values": {
        "12:image": "/root/并发/image/image_20260709-010435_c7faf2.png"
      }
    },
    {
      "id": "job-mirror",
      "target_url": "https://u123-app.openbayes.net",
      "input_values": {
        "12:image": "https://example.com/in2.png"
      }
    }
  ]
}
响应示例
{
  "success": true,
  "results": [
    {
      "id": "job-local",
      "target": "local",
      "success": true,
      "prompt_id": "…",
      "client_id": "concurrent-job-local-abc"
    },
    {
      "id": "job-mirror",
      "target": "mirror",
      "success": true,
      "prompt_id": "…",
      "client_id": "concurrent-mirror-job-mirror-xyz"
    }
  ]
}

在指定主机上提交一组任务（target_url 为空则跑本机） workflow_id 必须是已保存的工作流。jobs 数组每项含 id、可选 target_url（镜像机面板地址，省略或空字符串=本机主控）、input_values。服务端会对本地绝对路径文件自动读取并上传到目标 ComfyUI。同步并发提交，返回 results（含 prompt_id、client_id），后续用 poll/result 或 WebSocket 拿进度与产物。多任务场景更推荐 run-batch-async。

POST /api/concurrent/run-batch
请求体
{
  "workflow_id": "example-workflow.json",
  "jobs": [
    {
      "id": "job-1",
      "input_values": {
        "12:image": "https://example.com/a.png"
      }
    },
    {
      "id": "job-2",
      "input_values": {
        "12:image": "https://example.com/b.png"
      }
    }
  ]
}

同步批跑（队列调度 + 失败重试，阻塞直到全部任务结束才返回） 面板会自动按机器忙闲做动态分配：空闲镜像机立即接收任务，全部机器都忙时任务留在队列等待；扩容（加镜像机）后未开始任务可被新机器接管。耗时长，建议异步版本。

POST /api/concurrent/run-batch-async
请求体
{
  "workflow_id": "example-workflow.json",
  "jobs": [
    {
      "id": "job-1",
      "input_values": {
        "12:image": "https://example.com/a.png"
      }
    }
  ]
}
响应示例
{
  "success": true,
  "run_id": "run-9f3c…"
}

推荐：异步批跑，立刻返回 run_id，再用 status 接口轮询 请求格式与 run-batch 相同。提交后立即返回 run_id；后台持续按空闲机器派发队列任务，机器忙时不丢任务、只排队等待。用 GET /api/concurrent/run-batch-status?run_id=… 拉进度；想取消用 run-batch-cancel。

GET /api/concurrent/run-batch-status?run_id=
调用示例
async function waitBatch(runId) {
  while (true) {
    const r = await fetch(`${BASE_URL}/api/concurrent/run-batch-status?run_id=${runId}`);
    const data = await r.json();
    console.log(`${data.done}/${data.total} 完成，错误 ${data.error} 个`);
    if (['completed','cancelled','error'].includes(data.status)) return data;
    await new Promise(r => setTimeout(r, 2000));
  }
}

查询异步批跑进度（按 run_id） status 取值：queued / running / completed / cancelled / error。results 数组里每项含 status（queued/running/done/error）、stage、progress（0~100）、retry_count。

POST /api/concurrent/run-batch-cancel
请求体
{
  "run_id": "run-9f3c…"
}

取消正在运行的批跑（已经在跑的任务会跑完，未开始的不再调度）

GET /api/concurrent/poll?mirror_url=&prompt_id=

GET /api/concurrent/result?mirror_url=&prompt_id=&source_host_name=&source_host_id=&workflow_id=
调用示例
const r = await fetch(

    prompt_id: 'abc-123',
    source_host_name: '镜像机-A',
    source_host_id: 'pro-xxx',
    workflow_id: 'my-workflow.json'
  })
);
const { files } = await r.json();
响应示例
{
  "success": true,
  "files": [
    {
      "original": "zealman_00001.png",
      "local": "1783530275672_zealman_00001.png",

主控代理：从镜像机拉回结果文件并写入集群资产目录 面板批量生成在镜像机任务完成后会调此接口，将产出下载到主控 `/root/ComfyUI/output/concurrent/` 并登记 manifest。workflow_id 可选，用于过滤高清放大等中间预览节点，只保留最终产出。返回 files[] 含 url（/output/concurrent/…）。

GET {target_url}/api/workflow/result?prompt_id={prompt_id}
调用示例
// job 来自 /api/concurrent/run-batch-status 的 results[]
const result = await fetch(
  job.target_url + '/api/workflow/result?prompt_id=' + job.prompt_id
).then(r => r.json());

for (const item of result.results || []) {
  const fileUrl = job.target_url + item.url;
  const blob = await fetch(fileUrl).then(r => r.blob());

  // 这里换成你自己的保存逻辑：
  // - 上传到 S3 / OSS / MinIO
  // - 写入你的业务项目目录
  // - 登记到自己的数据库
  await saveToYourProjectStorage({
    jobId: job.id,
    type: item.type,
    url: fileUrl,
    blob
  });
}
响应示例
{
  "success": true,
  "pending": false,
  "results": [
    {
      "type": "image",
      "url": "/output/2026/zealman_00001.png",
      "filename": "zealman_00001.png"
    }
  ]
}

无主控推荐：到实际执行任务的镜像机读取结果，再由用户程序自行保存 run-batch-status 的每个完成 job 会带 target_url 与 prompt_id。target_url 是那台镜像机的面板地址；prompt_id 是该机器上的任务 ID。用户自己的集群软件应直接请求 target_url + /api/workflow/result?prompt_id=...，拿到 results 后把文件下载到自己的项目目录、数据库、NAS 或对象存储中，而不是依赖面板内置的主控资产回收。prompt_id 同样仅存于该镜像机 ComfyUI 内存 history，镜像机或 ComfyUI 重启后即失效，须及时落库。

集群资产

2 个接口

对应面板「批量生成」结果预览与集群资产列表。镜像机任务完成后主控会调 `/api/concurrent/result` 下载并登记；本机任务完成后调 `/api/concurrent/record-local` 将 ComfyUI 产出复制到 `/root/ComfyUI/output/concurrent/` 并写入 manifest。`GET /api/concurrent/assets` 返回全部有效资产（按时间倒序），每项含 sourceHost、promptId、workflowId、url（`/output/concurrent/…` 预览地址）。

GET /api/concurrent/assets
调用示例
const r = await fetch(BASE_URL + '/api/concurrent/assets');
const { assets } = await r.json();
// assets[0].url → 可直接拼 BASE_URL 预览
响应示例
{
  "success": true,
  "assets": [
    {
      "localFile": "1783530275672_zealman_00001.png",
      "sourceHost": "镜像机-A",
      "sourceHostId": "pro-xxx",
      "originalFile": "zealman_00001.png",
      "promptId": "abc-123",
      "timestamp": 1783530275672,
      "workflowId": "my-workflow.json",
      "url": "/output/concurrent/1783530275672_zealman_00001.png"
    }
  ]
}

列出主控登记的集群生成资产（manifest + 本地文件校验） 只返回 manifest 中且本地文件仍存在的条目。assets[] 每项含 localFile、sourceHost、sourceHostId、originalFile、promptId、timestamp、workflowId、url。

POST /api/concurrent/record-local
请求体
{
  "prompt_id": "abc-123",
  "workflow_id": "my-workflow.json",
  "source_host_name": "本机（主控）",
  "source_host_id": "__local__",
  "files": [
    {
      "filename": "zealman_00001.png",
      "type": "output"
    }
  ]
}
响应示例
{
  "success": true,
  "files": [
    {
      "original": "zealman_00001.png",
      "local": "1783530275672_zealman_00001.png",
      "url": "/output/concurrent/1783530275672_zealman_00001.png"

本机任务完成后：复制 ComfyUI 产出到集群资产目录并登记 面板在本机 ComfyUI 任务完成时调用。files 来自 `/api/workflow/result` 或 history 的 outputs；每项含 filename、type（output/temp）、可选 subfolder。source_host_name / source_host_id 可选，默认「本机（主控）」/ `__local__`。
